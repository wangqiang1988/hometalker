# FooTalker · 家庭内网对讲

部署在自己家里的服务器上，用手机浏览器打开就能像对讲机一样说话。

- **一个固定房间**（`home`），不需要注册、不需要账号，填个昵称 + 家庭口令就能进
- **按住说话**，同一时刻只有一个人能说，像真对讲机一样
- **纯内网**，语音不经过任何第三方，也**不落盘、不录音**
- **加到手机桌面**后像原生 App 一样全屏运行

## 它是怎么工作的

```
   手机浏览器                     你的内网服务器
 ┌──────────────┐            ┌───────────────────────────┐
 │  Web App     │  WSS       │  Caddy :443                │
 │  PWA         │◄──────────►│   TLS 终止 (本地 CA 签发)   │
 │              │            │            │               │
 │  AudioWorklet│            │            ▼               │
 │  采集/播放   │            │  server :8443 (Node)       │
 └──────────────┘            │   · 口令校验                │
                             │   · 麦权状态机              │
                             │   · 音频字节转发(不编解码)   │
                             └───────────────────────────┘
```

- **控制消息**走 WebSocket 的 JSON 文本帧，**音频**走二进制帧（浏览器原生区分这两种帧）
- 音频格式：16 kHz / 单声道 / Int16LE / 20 ms 一帧，**服务端只搬字节不编解码**，CPU 占用接近 0
- 浏览器侧的采集/播放用 `AudioWorklet` + `AudioContext({sampleRate:16000})`，整个音频图原生跑 16 kHz，不用手写重采样
- 麦克风自带浏览器的回声消除（AEC）、降噪（NS）、自动增益（AGC）

**为什么必须用 HTTPS**：浏览器的 `getUserMedia`（麦克风）只在**安全上下文**可用。`http://192.168.1.50` 不是安全上下文，Chrome / Safari 会直接禁用麦克风 —— 结果就是「能听不能说」。这是浏览器的硬性限制，没有绕过的办法。

## 部署

### 1. 准备

- 一台能跑 Docker 的机器（NAS / 树莓派 / 迷你主机 / 任意 Linux 主机）
- 服务器在家庭 Wi-Fi 里的**固定 IP**（见[局域网设置](#局域网设置)）
- 路由器没有占用 443 端口（或接受用 8443）

### 2. 配置

```bash
git clone <你的仓库> footalker
cd footalker
cp .env.example .env
vi .env
```

`.env` 至少要改这两项：

```ini
SITE_ADDR=192.168.1.50      # 你服务器的固定 IP
FAMILY_CODE=你的家庭口令     # 至少 4 个字符
```

> `FAMILY_CODE` 没设置时服务会**拒绝启动** —— 这是故意的，避免忘记设口令导致任何连上你家 Wi-Fi 的人都能进房间收听。

### 3. 启动

```bash
docker compose up -d --build
docker compose logs -f
```

看到 `房间 "home" 已启动` 就好了。

### 4. 导出根证书并发给家人

```bash
docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt ./rootCA.crt
```

把这个 `rootCA.crt` 通过微信 / AirDrop / 网盘发给家里人，按照下一节装到手机上。

> 根 CA 有效期 10 年。**只要根 CA 不变，以后换 IP 或换域名都不用重新装证书**，只需改 `.env` 里的 `SITE_ADDR` 再 `docker compose restart caddy`。

## 给手机装证书（必读）

Caddy 用自己的本地 CA 给你的 IP 签证书。手机必须**信任这个根 CA**，否则 Safari / Chrome 会拦截页面（iOS 尤其严格，**不装根证书的话连"继续访问"的选项都没有**）。

### iPhone / iPad

> ⚠️ **两步都要做**，只做第一步的话 Safari 仍然会拦截。

**第一步：安装描述文件**

1. 把 `rootCA.crt` 传到手机（AirDrop / 微信文件传输助手 / 邮件）
2. 打开这个文件，会提示「已下载描述文件」
3. 打开 **设置 → 通用 → VPN 与设备管理**
4. 在「已下载描述文件」里点 **Caddy Local Authority** → 右上角「安装」→ 输锁屏密码 → 「安装」

**第二步：开启完全信任**

1. 打开 **设置 → 通用 → 关于本机 → 证书信任设置**
2. 找到 **Caddy Local Authority**，把开关**打开**
3. 顶部出现「完全信任的根证书已启用」就对了

**第三步（可选）：添加到主屏幕**

1. 用 **Safari** 打开 `https://192.168.1.50`
2. 点底部「分享」按钮 → **添加到主屏幕**
3. 之后从桌面图标打开，就是全屏无地址栏的 App 体验

### Android

**安装 CA 证书**

1. 把 `rootCA.crt` 传到手机
2. 打开 **设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书**
3. 在文件管理器里选中 `rootCA.crt` → 确认安装
   （部分机型路径是：设置 → 安全 → 更多安全设置 → 加密与凭据 → 安装证书）
4. 输入锁屏密码

**添加到主屏幕**

1. 用 **Chrome** 打开 `https://192.168.1.50`
2. 右上角菜单 → **添加到主屏幕 / 安装应用**

### 验证

打开 `https://192.168.1.50`：

- ✅ 浏览器地址栏**没有**「不安全」提示 → 证书装对了
- ❌ 显示 `ERR_CERT_AUTHORITY_INVALID` → 根 CA 没装好或没开启完全信任

## 局域网设置

### 服务器要固定 IP

路由器 DHCP 租约一换，证书就失效了（证书里写的是 IP）。二选一：

- 在路由器上给服务器做 **DHCP 保留 / 地址绑定**
- 或者在服务器上手动设置静态 IP

改 IP 之后：改 `.env` 的 `SITE_ADDR` → `docker compose restart caddy` → **手机不用重新装证书**。

### 必须在同一个子网

所有家人设备要连**同一个 Wi-Fi**，且不能被路由器隔离：

- ❌ 关掉路由器的 **AP 隔离 / 客户端隔离 / 访客网络** —— 开了就连不上
- ❌ 别让一部分人连主 Wi-Fi、另一部分连访客网络
- 5GHz 和 2.4GHz 是同一个 LAN，一般没问题，但如果路由器做了频段隔离也要关掉

### 443 端口被占用？

有些路由器的管理界面占用 443。改 `.env`：

```ini
HTTPS_PORT=8443
```

```bash
docker compose up -d
```

然后手机访问 `https://192.168.1.50:8443`（端口号不参与证书校验，不影响 HTTPS）。

## 使用

1. 手机浏览器打开 `https://<你的IP>`
2. 填**昵称**（如"妈妈"）和**家庭口令** → 点「进入」
   - 首次会请求麦克风权限，允许即可
   - 之后昵称和口令会记在本机，下次直接进
3. 在房间里点**底部大按钮**开始说话，松开结束

### 界面说明

| 元素 | 含义 |
|---|---|
| 顶部 `home · N 人在线` | 房间名和在线人数 |
| 成员列表 | 在线的人，说话的人会高亮并标注「说话中」 |
| 中间状态条 | 显示「XXX 正在说话…」 |
| 底部大圆按钮 | **按住说话**（松手即结束） |
| 黄色条 | 本地麦克风电平 |
| 蓝色条 | 远端收到的声音电平 |
| ⚙ 按钮 | 收听音量、麦克风增益、清除本机信息 |

### 关于抢麦

默认是**抢占**模式：你按住说话就会直接接管麦，正在说话的人会被自动打断。觉得太容易打断的话，把 `.env` 里改成：

```ini
SPEAK_MODE=exclusive
```

这样别人在说话时你会收到「XXX 正在说话」的提示，必须等他松手。

### 建议

- **说话人尽量戴耳机**。网页没法把 iPhone 的输出切到「听筒」，外放时你自己会听到回声（浏览器的 AEC 能压掉大部分，但戴耳机最干净）
- **按住说话时屏幕不会熄灭**（应用会自动申请屏幕常亮），别手动锁屏
- 锁屏后网页会被浏览器冻结导致断线，**回到前台会自动重连**，不用管

## 配置项

全部在 `.env` 里：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SITE_ADDR` | `192.168.1.50` | 内网 IP 或域名，写进证书 SAN |
| `FAMILY_CODE` | **必填** | 家庭口令，至少 4 个字符 |
| `ROOM_NAME` | `home` | 房间显示名 |
| `PORT` | `8443` | server 内部端口 |
| `HTTPS_PORT` | `443` | 对外暴露的 HTTPS 端口 |
| `MAX_MEMBERS` | `12` | 房间人数上限 |
| `MAX_SPEAK_MS` | `60000` | 单次发言最长时长，超时自动放麦 |
| `SPEAK_MODE` | `preempt` | `preempt` 抢占 / `exclusive` 拒绝 |
| `LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error` |

改完 `docker compose restart server`（改 `SITE_ADDR` 则要 `restart caddy`）。

## 开发与自测

```bash
# 装依赖
npm --prefix server install
npm --prefix web install

# 构建
npm run build          # 前端 + 后端
npm run icons          # 重新生成 PWA 图标（纯 Node，无外部素材）

# 本地起服务（不用 Docker）
cd server && FAMILY_CODE=dev1234 PUBLIC_DIR=../web/dist node dist/index.js

# 前端开发服务器（自动代理 /api 和 /ws 到 8443）
cd web && npm run dev
```

### 自测脚本

三个脚本，都会输出 `✓ / ✗` 和汇总：

```bash
# 1) 协议层：鉴权、在线状态、麦权、音频转发（19 项）
node scripts/smoke.mjs

# 2) 服务端行为：抢麦模式、发言超时、断线放麦（9 项）
#    先用 SPEAK_MODE=exclusive MAX_SPEAK_MS=1500 起服务再跑
node scripts/behavior.mjs

# 3) 真实浏览器端到端：麦克风 → worklet → WebSocket → 服务端 → 另一端播放（19 项）
#    需要 Chrome 和 puppeteer-core：npm i -D puppeteer-core
node scripts/browser-e2e.mjs
```

`smoke.mjs` 支持测 WSS：

```bash
SMOKE_URL=wss://192.168.1.50/ws SMOKE_INSECURE=1 node scripts/smoke.mjs
```

## 排障

| 现象 | 原因 / 解决 |
|---|---|
| 打开是「不安全」警告 | 根 CA 没装好。检查上面的 iOS **两步**、Android 一步 |
| 页面打得开但**按说话没反应** | 麦克风权限被拒。检查浏览器地址栏的权限图标，重新允许 |
| 完全**听不到别人说话** | ① 检查音量条 ② 收听音量滑到最大 ③ 看蓝色电平条有没有动 ④ 说话人是不是戴耳机导致外放被静音 |
| **一直重连中** | ① Wi-Fi 断开了 ② 服务器挂了（`docker compose logs`）③ 路由器 AP 隔离 |
| 手机上**打不开 https** | ① 证书没装 ② IP 变了（改 `SITE_ADDR` 后重启 caddy）③ 手机不在同一子网 |
| Android 提示**证书无效** | 用户 CA 装错位置了，要选「CA 证书」不是「VPN 和应用」 |
| 说话有**回声** | 说话人戴耳机，或把手机放远一点 |
| 重新部署后**白屏** | 正常。强制刷新页面（Ctrl+Shift+R）或删除 PWA 缓存。服务端已做 mtime 校验，不会再发旧资源 |
| 提示「**口令错误次数过多**」 | 连续输错 10 次会锁 60 秒，等一分钟即可 |

看服务端日志：

```bash
docker compose logs -f server
docker compose logs -f caddy
```

## 已知限制

1. **iOS 无法强制切到"听筒"输出**（网页没有 `setSinkId` API）。外放说话时自己会听到回声，靠浏览器 AEC 缓解，**戴耳机最干净**
2. **手机锁屏 / 切后台 → 网页被浏览器冻结 → 断线**。这是浏览器的限制，网页方案无解。回前台会自动重连
3. **音频延迟比原生 App 大 100~200 ms**（20 ms 帧 + 抖动缓冲）。对讲场景可接受
4. **不能同时多人说话**（半双工）。这是对讲机语义
5. **只在家里 Wi-Fi 下用**。出门后连不上（除非你自己加 VPN / 内网穿透）
6. **服务端能听到明文 PCM**（它只在内存里转发，不落盘、不录音）。但请相信家里那台机器
7. **换浏览器/清缓存后要重装证书**吗？不用 —— 根 CA 十年有效，装一次就够

## 安全说明

- 语音**不经过任何第三方**，全部在你家局域网内点对点传输（客户端 → 你的服务器 → 其他客户端）
- 语音**不落盘、不录音**、服务端不保留任何历史数据
- 口令用**恒定时间比较**（`timingSafeEqual`），防时序侧信道
- 口令错误 10 次锁 60 秒，防暴力猜解
- 口令**不放进 URL**，避免进日志和浏览器书签
- 口令错误时**不会**被存到手机本机
- Caddy 关闭了管理端点、移除了 `Server` 响应头、加了 `X-Content-Type-Options: nosniff`
- 服务端无状态，重启不丢数据；唯一的持久化是 Caddy 里的证书

### 如果要暴露到公网

本项目**没有**为公网部署做加固（没有 HTTPS 限速、没有 IP 白名单、没有审计）。真要开放到公网，请自行加一层反向代理做限流，或者干脆用 Tailscale 组网只让家人访问。
